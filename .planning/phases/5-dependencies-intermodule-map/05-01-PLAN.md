  <name>Tarea 1: Inventariar dependencias PHP de producción</name>
  <files>.planning/phases/5-dependencies-intermodule-map/DEPENDENCIAS-EXTERNAS.md</files>
  <action>
    Usa `mcp__project2context__search_files` para leer composer.json completo.
    Para cada paquete en "require" (no "require-dev"):

    Clasifica cada paquete en una de estas categorías:
    - **Framework core**: laravel/framework, filament, livewire (sin los cuales nada funciona)
    - **Crítico para negocio**: paquetes de lógica de negocio DCS (no son utilidades)
    - **Integración externa**: SDKs de sistemas externos
    - **Seguridad/Auth**: paquetes de autenticación, cifrado, permisos
    - **Infraestructura**: cache, queue, storage, logging
    - **Utilidades**: helpers generales (collections, strings, dates)

    Para cada paquete crítico para negocio e integración externa:
    - ¿Puede ser reemplazado en la reescritura? ¿Por qué alternativa?
    - ¿Tiene licencia restrictiva? (revisar licencia conocida del paquete)

    Crea DEPENDENCIAS-EXTERNAS.md con sección "## Dependencias PHP de Producción":
    Tabla por categoría: | Paquete | Versión | Propósito | Reemplazable | Notas |
  </action>
  <verify>DEPENDENCIAS-EXTERNAS.md con tabla de paquetes PHP de producción clasificados por categoría.</verify>

<task type="auto">
  <name>Tarea 4: Identificar dependencias críticas para la reescritura</name>
  <files>.planning/phases/5-dependencies-intermodule-map/DEPENDENCIAS-EXTERNAS.md</files>
  <action>
    Basándote en las tareas 1-3, agrega sección "## Dependencias Críticas para la Reescritura":

    Para cada dependencia que cumpla uno o más de estos criterios:
    - Es un SDK de sistema externo sin alternativa directa
    - Tiene lógica de negocio DCS embebida (no solo utilidades)
    - Está obsoleta o sin mantenimiento (detectar por versión muy antigua o última publicación)
    - Tiene licencia restrictiva (GPL, LGPL — incompatible con comercialización independiente)
    - Es tan personalizada que requiere reescritura propia

    Documenta:
    | Paquete | Versión | Razón de Criticidad | Nota para Reescritura |

    Donde "Nota para Reescritura" puede ser:
    - "Replicar internamente"
    - "Buscar alternativa moderna"
    - "Mantener con wrapper"
    - "Migrar al nuevo estándar [X]"
    - "Requiere decisión de licenciamiento"
  </action>
  <verify>Sección "## Dependencias Críticas para la Reescritura" con tabla y notas de migración.</verify>
