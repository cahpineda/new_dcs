<task type="auto">
  <name>Tarea 2: Identificar hotspots de alta complejidad de separación</name>
  <files>.planning/phases/2-functional-module-identification/LIMITES-MODULOS.md</files>
  <action>
    Basándote en las dependencias cruzadas identificadas, determina los hotspots de mayor riesgo:

    Un hotspot es cualquier elemento que:
    - Es referenciado por 3+ módulos distintos
    - Tiene dependencias bidireccionales
    - Es una tabla DB compartida por múltiples módulos con FK cruzadas
    - Es un servicio con lógica de múltiples dominios mezclados

    Usa `mcp__project2context__dispatch_map` o `mcp__project2context__export_core_network` si están disponibles para obtener el grafo de dependencias.

    Documenta en LIMITES-MODULOS.md bajo "## Hotspots de Alta Complejidad":
    Para cada hotspot:
    - Nombre del elemento (clase, tabla, servicio)
    - Ruta real en el repositorio
    - Módulos afectados
    - Nota de complejidad de migración: Alta / Media
    - Estrategia sugerida: "extraer como servicio compartido" / "duplicar por módulo" / "migrar con API interna"
  </action>
  <verify>Sección "## Hotspots de Alta Complejidad" con elementos reales y nota de complejidad de migración.</verify>
  <done>Hotspots documentados con estrategia sugerida para la reescritura.</done>
</task>

<task type="auto">
  <name>Tarea 3: Validar y ajustar lista final de módulos</name>
  <files>.planning/phases/2-functional-module-identification/LIMITES-MODULOS.md</files>
  <action>
    Basándote en el análisis de dependencias y hotspots:
    - ¿Algún "módulo candidato" tiene demasiado acoplamiento para ser independiente? → Considerar fusionarlo con otro.
    - ¿Algún módulo muy grande debería dividirse? → Identificar subdominio natural.

    Documenta en LIMITES-MODULOS.md bajo "## Lista Final de Módulos Validada":
    - Lista final de módulos con nombre, descripción de 1 línea, nivel de acoplamiento (Alto/Medio/Bajo)
    - Para módulos con Alto acoplamiento: nota explicando el riesgo para la reescritura
    - Módulos que se fusionaron (si aplica): justificación

    Esta lista final es el output principal que alimenta las fases 3-5 del análisis.
  </action>
  <verify>Sección "## Lista Final de Módulos Validada" con módulos, nivel de acoplamiento, y notas de riesgo.</verify>
  <done>Lista final de módulos validada y documentada con nivel de acoplamiento.</done>
